## Sharing overlay

An `Overlay` is sharing syntax over the core language and holds no policy: which part of a shared leg a duplication copies is `DuplicationPolicy::copies`'s answer, asked by the walk that duplicates. It keeps one flat vector per core family — values, computations, value types, computation types — so an id's type names its family and its polarity, and teardown is four flat vector drops. A node is one of four kinds and nothing else: **opaque**, a core node held by id; **bound**, one occurrence of a shared leg, named by its distance — how many shares lie between it and its own — and its position among that share's occurrences; **shared**, `body[x₀ … xₙ₋₁ ← leg]`, a body holding exactly `arity` occurrences of one leg of any family, standing in its body's family; and **grafted**, one core former over overlay children, with one graft arm per core former. A node is minted only over children the overlay holds, so every child is older than its parent and the overlay is acyclic across families.

`Overlay::validate` walks one root in preorder on a heap task stack, with a frame per share whose body it is inside. A leg stands outside its own share's scope, so an occurrence in a leg counts from the shares around that share. An occurrence closes when its distance names an open frame whose leg is of the occurrence's family, at that frame's next position and below its arity; a share closes when its arity is non-zero and its body reaches it exactly. A position is therefore the occurrence's preorder rank among its share's, never a free choice.

Sharing is explicit or absent: a node reached twice from one root is refused. Every node then has one parent, so a walk enters each node once, and an overlay whose expansion doubles per link validates in its own size rather than its expansion. Alternatives: admitting implicit reuse and walking it as a tree, which costs the expansion the overlay exists to remove; a graft as a template term with seam placeholders, which adds a seam syntax with its own spelling, order and linearity rules to say what one former per graft says; and named occurrences, which need a fresh-name supply and a capture check. Reversal: a producer that cannot name its shares — one that hash-conses after the fact — needs reuse admitted, and the walks a visited table in place of the reached-once rule.

## Erasure

`erase_value`, `erase_computation`, `erase_value_type` and `erase_comp_type` take an overlay root and the core arena its opaque nodes name, validate, and mint the core term the root stands for: each graft one core node after its children, left to right; each opaque node its core id as it stands; each share's leg once, before its body, and every occurrence that one id. They take no policy, so the output is a fact about the overlay alone, and it is the unshared pipeline's input: no share survives, and evaluation walks each occurrence of the leg's id as a copy, which is `DuplicationStance::EraseAndClone` and the reference every finer stance replays against. A refusal is named — `EraseFault::Refused` with the validation refusal, or `EraseFault::UnresolvedOpaque` for a core id the arena does not hold — and the core arena is truncated back to its entry watermark, so erasure is total: an erased term or no change.

Because the minting order is fixed, "byte for byte" has a definite meaning: the erased arena equals, under the core arena's own equality, the arena a hand-built unshared term mints when built in the same order. The deep evaluation, readback and teardown cases are each built twice, by hand and as an overlay, and compared that way, then run through the unshared pipeline to equal domain arenas, core arenas and results.

Indices are copied, never shifted: a leg's free index names, at each occurrence, the binder it reaches from there, the reading a core DAG gives a node reached twice. Alternatives: cloning the leg at every occurrence, which makes the output exponential in a chain of shares; and shifting the leg's indices by the binders between its share and each occurrence, which mints a copy per occurrence under a binder and changes the reading from the core DAG's. Reversal: a producer that places shares outside the binders their legs read, and needs substitution's reading, makes erasure shift and stop being node for node.

## Sharing measure

`SharingMeasure::of` validates an overlay root, then walks it once in post-order on a heap task stack and reports five quantities, each its own counter type: `ShareCount`, the share nodes the root reaches; `OccurrenceCount`, their arities summed; `ShareDepth`, the most shares on one path down from the root, through legs and bodies alike; `NodeCount`, the nodes the root reaches; and `ExpansionSize`, the node count of the term the root stands for with every share's leg inlined at each of its occurrences, where a graft is one node over its children, an opaque node is one node, and a share and an occurrence are nothing of their own. The expansion is the part of the unshared machines' walk that sharing changes: what evaluation walks when it takes each occurrence of an erased leg's id as a copy. The quantities are He's strong-normalisation measure for sharing reductions, read over the overlay. The duplication walk prices the copying stance by them before it mints, since that stance's output is the root's whole expansion, and the [measurement](#measurement) compares the two stances in them.

The walk measures each leg once, keeps its measure on a stack of the legs in scope, and reads it at every occurrence, so it enters each node once and costs the reachable overlay, never its expansion: validation's refusal of a node reached twice is what makes one visit per node enough. A chain of sixty-three shares whose expansion doubles per link holds 253 nodes and measures exactly `u64::MAX`. Every addition is checked, and a sum past its 64-bit counter is refused as `MeasureFault::Overflow`, naming the `MeasuredQuantity` and the node where the sum passed it, so the same chain one link longer is refused at that link's pair. A validation refusal arrives unchanged as `MeasureFault::Refused`, before anything is counted. The measure is a function of the structure its root reaches: no id, other root or later parent changes it.

Alternatives: index arithmetic over one arena minted child before parent, which the overlay's four family vectors, with no order across them, cannot support; a walk over the expansion, which costs what it measures on a doubling chain; a saturating counter, which reports a cost the unshared pipeline cannot pay as if it could; and a weakening count beside the shares, which has nothing to count, since validation refuses a share of arity zero and a weakening is therefore an absent share. Reversal: the overlay admits shares of arity zero, and the weakening count returns beside the five.

## Duplication walk

`duplicate_value` and `duplicate_computation` validate a root, then rebuild everything it reaches into fresh nodes appended to the same overlay, asking `DuplicationPolicy::copies`, share by share, what to do with each part of the leg. A leg that is no abstraction is one rib: copied, the share is **inlined**, its leg walked afresh at each occurrence and the share gone; shared, the share is **kept**, its leg rebuilt once and every occurrence pointing at it. A leg that is an abstraction — a lambda, or a thunk over one — has a **spine**, the paths from its binder down to the binder's occurrences, and **ribs**, the maximal subterms of its body that do not read the binder. Both parts copied, the share is inlined; the spine shared, it is kept; the spine copied and the ribs shared, it is **distributed**: each rib becomes the leg of a new share standing where the abstraction's share stood, and each occurrence of the abstraction becomes a copy of its spine whose ribs are occurrences of those shares. That is the λ-distributor of He's atomic calculus in the overlay's terms, with the distributor itself never minted: its cursor — the frame of its first rib share and the ribs found so far — lives on the walk's heap task stack, beside the output frames and the covers of the shares inside a leg the walk reads in scope.

Erasure reads a leg's indices where each occurrence stands, so a subterm moved into a share's leg reads, at its own position, what it read before. A subterm is a rib when its expansion does not read the binder — the binder's index, counted from where the subterm stands, is not among its free indices, an occurrence of an outer share reading its leg's and an opaque node its core term's — and when no occurrence inside it names a share opened inside the abstraction's leg, whose frame would not enclose the rib's new share. Ribs are sought through the body and through the bodies of the shares nested in it; a nested share's leg is read where its occurrences stand, so the binder's index there is no single number, and that leg travels with the spine. New rib shares are not distributed again in the same walk. When the policy copies every rib the output is the root's whole expansion, so the walk measures the root first and refuses, before minting anything, an expansion past the ids an overlay family holds as `DuplicationFault::ExpansionPastIds` and one past the measure's counter as `DuplicationFault::Measure`. A sharing stance mints at most the expansion and two nodes per rib, and every refusal leaves the overlay at its entry watermark.

The walk runs once over the whole root, before evaluation, and shares every maximal rib, a leaf or a variable included. The recorded design enters the walk where a shared abstraction is forced into a redex. An environment machine re-evaluates an abstraction's body at every application, so what a walk at the redex would buy — a rib evaluated once across applications — is bought by lifting each rib into a leg of its own once and letting the evaluator remember a leg's evaluation ([Closed-configuration sharing](#closed-configuration-sharing)); a walk at every β would rebuild one spine per application for no sharing the evaluator does not already have. Alternatives: a cache keyed on core node ids inside the machines, which makes the sharing decision behind the parameter's back ([Source sharing](#source-sharing)); a node kind for distributors, which turns a reduction artifact into overlay surface that every producer would emit and validation would check; and the walk per redex, which rebuilds the spine at each application. Reversal: the [measurement](#measurement) shows no deep case where the spinal stance evaluates in fewer steps than the reference at equal results, and the walk goes while the stance stays gated; a workload where leaf ribs cost more steps than they save copies the ribs below a size with the spine; a stance that must decide per application moves the walk to the redex.

## Overlay evaluation

`eval_overlay_value` and `eval_overlay_computation` are the reference: erase the root into the core arena, then run the unshared machine over the erasure in the empty environment. The reference is pinned before any stance enters. The core and domain arenas it mints equal node for node those erasure followed by `eval_value` or `eval_computation` mints, with the same result and the same unspent fuel, on every deep evaluation case and, through readback, on every deep readback case. A refusal arrives in its own vocabulary as `OverlayEvalFault`: erasure's leaves the core arena as it found it, and the machine's keeps the erasure.

## Closed-configuration sharing

Under the spinal stance, `TracedDuplication` evaluates a root through its own duplicate: it duplicates the root, erases the duplicate keeping each share's erased leg, and hands those legs to the machine. The first evaluation of a leg in one **configuration** — one binding at each of its free indices, in both zones — is remembered, and every later occurrence read in that configuration takes it; a leg read under another binding is evaluated again, and a leg with an index the environment does not bind is never remembered. Erasure copies a leg's indices unshifted, so a free index names, at each occurrence, the binder it reaches from there, and one evaluation serves two occurrences exactly when those binders hold the same entries. A rib is the case the stance is for: it does not read the binder its abstraction duplicates, so its evaluation is shared across every application of one closure. The memo lives for one evaluation; readback and `decide` stay unshared. The duplicate is scratch, and the overlay is truncated back to its entry watermark whatever the outcome.

Sharing stays inside the weak-head machine, where configurations are closed and the confluence and normalisation results for sharing reductions apply, so a schedule choice can cost a spurious decline, never a wrong certification. Alternatives: shifting a leg's indices per occurrence, which mints a copy per occurrence under a binder and changes erasure's reading ([Erasure](#erasure)); and sharing open configurations on the strength of results stated over simply-typed systems, which type no fragment of this language. Reversal: a confluence result for open terms under strong reduction covers the core's formers, and sharing extends past the weak-head machine.

## Certifying path

A spinal run exists only with a trace sink attached. `DuplicationPolicy::new(DuplicationStance::Spinal)` keeps refusing with `PolicyRefusal::StanceGated`; `TracedDuplication::install` takes the sink the conversions decided under the stance record into, and refuses the spinal stance with `PolicyRefusal::Untraced` when that sink retains nothing, which `TraceSink::ACTIVITY` states at compile time. The installation owns every duplication, evaluation and `decide` run under the stance, and the policy it holds never leaves it, so a verdict over a domain value the spinal stance shaped carries the derivation the kernel replays by construction rather than by a caller's care. The erase-and-clone stance installs with any sink and evaluates through the reference.

Replay does not depend on the stance: the kernel re-executes the decisions over its own unshared terms, sequentially, and never reads the overlay, so a spinal verdict is certified exactly when its trace replays, and a shared evaluation that answered differently from the unshared one surfaces as a refused trace rather than as an accepted verdict. This crate's tests compose the two through the kernel's replay, a development dependency: the kernel agrees with every spinal catalogue and ladder verdict, and when the height-weighted schedule spends its budget on a divergence the fair schedule steps around, the run declines with no derivation and the kernel declines with it, never reading the decline as a refutation.

Alternatives: caller discipline — `new` admits the stance and the crate README tells callers to replay — which leaves an uncertified verdict one call away; and replay inside this crate, a production edge from the untrusted machine onto the trusted base that every call pays. Reversal: `gandr-core-checker` composes the conversion machine with the kernel's replay at its conversion boundary, as the only such composition; the certifying constructor then moves behind it.

## Measurement

The measure's five quantities of what each stance hands the evaluator, and the evaluator's steps to weak head, per deep case. Under erase-and-clone the evaluator walks the expansion, so its row is the copying duplicate's measure; under the spinal stance the row is the spinal duplicate's. No deep case shares an abstraction, so each spinal duplicate keeps every share and measures as its input; the [full-laziness witnesses](../README.md#provided-features) are where ribs are distributed. The doubling chain is the teardown case's value family, measured at sizes the reference can finish and at its own length.

Where the shared leg is a leaf — the value chain's unit, the curried application's argument — remembering it costs one step and saves none. ## Source sharing

A core term is a DAG, and both machines walk it as a tree: evaluation evaluates a node reached twice twice, and readback mints a fresh core node per rebuilt domain node. A term with deep sharing costs its expansion, bounded by the fuel budget. Removing that cost is the duplication parameter's job, over the sharing overlay: the evaluator remembers a leg's evaluation only when the installed stance handed the leg over as a share ([Closed-configuration sharing](#closed-configuration-sharing)), and readback and conversion still walk the expansion. A cache keyed on the source node inside a machine would make the sharing decision behind the parameter's back.

## Not provided

- **The μ-distributor arm.** He's calculus distributes a stack-capturing abstraction in the λ-distributor's shape: the constructor frozen in place, the body's copies made as one tuple sharing the body. No core former binds into `Zone::Linear`, so a duplication never meets a stack capture and an arm would have no input a test could reach; building it against a hand-opened linear context would test a configuration no term reaches. Reversal: a core former binds into `Zone::Linear`; the walk then gains the arm in that shape, asking the linear zone's one-shot discipline before it copies a capture rather than deciding that again.
- **The spinal granularity stance.** `GranularityStance::Spinal` stays refused with `PolicyRefusal::GranularityGated` ([Granularity stance](../README.md#granularity-stance)): duplication decides what one evaluation shares, while the granularity decides how finely the conversion machine shares its channels, and the second waits on evidence the first produces. Reversal: with the spinal duplication differential green, a measurement shows the skeleton's channels re-evaluating a shared partial application.
